# Лекция 7 — Фичи, User Stories, User Flows

Документ оформляет требования по фреймворку:
**Фича → User Story → User Flow** (как ведёт себя пользователь).

Use Cases (BDD Gherkin) и NR/NFR с ID — в файлах `02-use-cases-bdd.md` и `03-requirements.md`.

Каждая Story имеет идентификатор `US-F{feature}-{n}`. Каждый Flow — `UF-F{feature}-{n}`.

## F1 — Сервис генерации видео в Hedra

**Цель.** Превратить текст слайда + одну фотографию + голос «aisala» в говорящий аватар-MP4 через Hedra API на VM `human-1`.

### US-F1-1 — Запуск пайплайна одной командой
Как инженер платформы, я хочу одной командой запустить генерацию всех 50 видео лекции, чтобы не нажимать в Hedra-UI по одной кнопке на каждый слайд.

#### UF-F1-1
1. Инженер подключается по SSH к `human-1` (gcloud compute ssh).
2. Клонирует ветку репозитория.
3. Экспортирует `HEDRA_API_KEY` в окружение.
4. Запускает `python l7/service/generate.py --lecture l7`.
5. Видит прогресс по слайдам в STDOUT и в `data/manifest.json`.
6. По завершении видит в `l7/videos/` файлы `1.mp4 .. 50.mp4`.

### US-F1-2 — Идемпотентность и докатка
Как инженер, я хочу, чтобы повторный запуск не пересоздавал готовые видео, а только догонял недостающие — потому что Hedra стоит денег и времени.

#### UF-F1-2
1. Инженер прерывает первый запуск на 23-м слайде.
2. Запускает скрипт второй раз.
3. Скрипт проверяет `videos/{1..50}.mp4` и manifest.
4. Для слайдов 1-22 пишет `skip: already generated`.
5. Для слайдов 23-50 продолжает работу.
6. Если был флаг `--regenerate 17`, перегенерирует только слайд 17.

### US-F1-3 — Прозрачные ошибки
Как инженер, я хочу видеть осмысленный лог при сбое Hedra (rate-limit, неверный voice, упавший ассет), чтобы быстро понять причину.

#### UF-F1-3
1. Hedra возвращает 429 / 5xx / `voice_not_found`.
2. Сервис ретраит с backoff (макс. 4 попытки).
3. При финальном фейле — слайд пишется в `manifest.failed`, остальная очередь продолжает.
4. По завершении сервис выводит сводку: `OK: 47 / FAILED: 3 (ids: 17, 28, 41)`.

## F2 — Конвейер «слайды → 50 видео»

**Цель.** Привязать структуру `slides.json` к выходному набору `videos/{id}.mp4`. Слайд = запись таблицы, видео = озвучка этой записи.

### US-F2-1 — Источник правды по контенту
Как преподаватель, я хочу, чтобы тексты озвучек хранились в одном машинно-читаемом файле (`l7/data/slides.json`), а не размазывались по HTML и скриптам.

#### UF-F2-1
1. Преподаватель редактирует `slides.json`: меняет `narration` у слайда 27.
2. Запускает `python l7/service/generate.py --regenerate 27`.
3. Получает обновлённый `27.mp4`.
4. HTML-плеер автоматически подхватывает новый файл при следующем открытии.

### US-F2-2 — Манифест артефактов
Как PM, я хочу видеть, какие слайды успешно озвучены, когда, длительностью какой и под каким хешем текста — без открытия видео.

#### UF-F2-2
1. PM открывает `l7/data/manifest.json`.
2. Видит для каждого слайда: `id`, `status`, `hedra_generation_id`, `file_sha256`, `duration_sec`, `generated_at`, `text_sha256`.
3. По изменению `text_sha256` понимает, что озвучка устарела и видео надо перегенерировать.

## F3 — Интерактивная страница лекции

**Цель.** Веб-страница `l7/index.html` показывает 50 слайдов с инфографикой и синхронным видео-аватаром, перетаскиваемым по экрану, как в примере `aisala/ai-agents-corp/6`.

### US-F3-1 — Листание слайдов
Как слушатель, я хочу листать слайды клавишами/мышью/свайпом, как в обычном слайд-плеере.

#### UF-F3-1
1. Слушатель открывает `l7/index.html`.
2. Видит титульный слайд + автоплей видео `1.mp4` в bubble.
3. Стрелка → / клик ЛКМ / свайп влево — следующий слайд + смена video.src.
4. Стрелка ← / ПКМ / свайп вправо — предыдущий.
5. Прогресс-бар отражает позицию.

### US-F3-2 — Перетаскиваемый видео-bubble
Как слушатель, я хочу перетащить видео-«пузырь» в любой угол экрана, чтобы он не закрывал инфографику.

#### UF-F3-2
1. Слушатель зажимает bubble мышью / пальцем.
2. Перетаскивает в нужный угол.
3. Bubble «прилипает» к границам экрана.
4. Позиция сохраняется в `localStorage` между сессиями.

### US-F3-3 — Управление видео
Как слушатель, я хочу ставить видео на паузу/возобновлять, видеть лоадер при буферизации, и не терять состояние при переключении слайдов.

#### UF-F3-3
1. Клик по bubble — pause/play.
2. При waiting — показывается лоадер.
3. На `ended` — иконка play.
4. При переключении слайда — src меняется, видео автостартует с muted=false после первого пользовательского клика.

### US-F3-4 — PDF-экспорт
Как преподаватель, я хочу экспортнуть слайды в PDF (печать), при этом видео не должно мешать вёрстке.

#### UF-F3-4
1. Преподаватель открывает `l7/index.html?pdf=1`.
2. Все 50 слайдов раскрываются вертикально.
3. Bubble и фон-glow скрыты.
4. Браузер печатает A4-альбомные.

## F4 — Публикация артефактов в Git

**Цель.** Готовые MP4 попадают в `l7/videos/` ветки `claude/setup-gcloud-video-service-XKVf0` и доступны по относительному пути из `index.html`.

### US-F4-1 — Чистый коммит видео
Как maintainer, я хочу, чтобы видео коммитились отдельным шагом и одним коммитом на пачку, без перезаписи кода.

#### UF-F4-1
1. После генерации сервис вызывает `git add l7/videos/`.
2. Создаёт коммит вида: `feat(l7): add hedra-generated videos {1..50}.mp4`.
3. Делает `git push -u origin claude/setup-gcloud-video-service-XKVf0` с retry-backoff (см. инструкции репо).

### US-F4-2 — Большие файлы не ломают репо
Как maintainer, я хочу, чтобы суммарный объём 50 видео не превышал разумный лимит и репо оставался клонируемым.

#### UF-F4-2
1. Перед коммитом сервис проверяет размер каждого MP4.
2. Если файл `> 25 MB`, пишет предупреждение и опционально перекодирует через ffmpeg.
3. Если суммарный объём `> 500 MB`, рекомендует переключиться на Git LFS (документировано, но не включается автоматически).

## F5 — Развёртывание на gcloud VM `human-1`

**Цель.** Сервис разворачивается одной серией команд на стандартной Debian/Ubuntu VM и не требует ручной настройки.

### US-F5-1 — Bootstrap VM
Как инженер, я хочу скрипт, который ставит Python, ffmpeg, git и клонирует репо.

#### UF-F5-1
1. Инженер делает `gcloud compute ssh human-1 ...`.
2. Запускает `bash l7/service/bootstrap.sh`.
3. Скрипт ставит зависимости, клонирует репо, переключается на нужную ветку.
4. Печатает «READY».

### US-F5-2 — Безопасное хранение секретов
Как инженер, я не хочу класть API-ключ Hedra в git. Ключ берётся из переменной окружения / Secret Manager.

#### UF-F5-2
1. Инженер `export HEDRA_API_KEY=sk_hedra_...` или подтягивает из gcloud Secret Manager.
2. Скрипт читает только `os.environ`, в коде ключа нет.
3. В `.gitignore` запрещено коммитить `.env`, `secrets/`, `*.key`.
