# Лекция 7 — Требования NR / NFR с ID

К каждому Use Case прикреплены функциональные (NR) и нефункциональные (NFR)
требования. ID — **обязательны**:

* `NR-F{feature}-{n}`  — Functional / behavior requirement
* `NFR-F{feature}-{n}` — Non-functional (performance, security, ops, UX)

Связь `UC → NR/NFR` — последний раздел.
Связь `NR/NFR → Test` — в `06-tests.md`.

---

## F1 — Сервис генерации видео

### Функциональные NR

| ID         | Требование                                                                                              |
|------------|---------------------------------------------------------------------------------------------------------|
| NR-F1-1    | Сервис загружает локальный JPEG в Hedra Asset API и сохраняет `asset_id` в manifest.                    |
| NR-F1-2    | Сервис создаёт generation-запрос в Hedra с моделью «Hedra Avatar 540p», 1:1, voice `aisala`.            |
| NR-F1-3    | Сервис поллит статус генерации каждые 5 секунд до состояний `complete` или `failed`.                    |
| NR-F1-4    | При `complete` сервис скачивает MP4 в `l7/videos/{slide_id}.mp4`.                                       |
| NR-F1-5    | При `failed` сервис записывает причину в manifest и продолжает с остальными слайдами.                   |
| NR-F1-6    | Поддерживаются HTTP-ретраи: 4 попытки, backoff 2/4/8/16s, по статусам 429 и 5xx.                        |
| NR-F1-7    | CLI принимает флаги `--lecture`, `--regenerate <ids>`, `--dry-run`, `--limit N`, `--from N`, `--to N`.  |
| NR-F1-8    | По завершении печатается сводка: `OK / SKIPPED / FAILED` со списком id.                                 |
| NR-F1-9    | Идемпотентность: если `videos/N.mp4` существует и `text_sha256` совпадает — слайд не пересоздаётся.     |
| NR-F1-10   | Все сетевые вызовы Hedra идут через единый клиент с тайм-аутами и логированием.                         |

### NFR

| ID         | Требование                                                                                                                |
|------------|---------------------------------------------------------------------------------------------------------------------------|
| NFR-F1-1   | Среднее время генерации одного слайда ≤ 4 минут (под нагрузку Hedra 540p, 1:1).                                            |
| NFR-F1-2   | Скрипт пишет structured JSON-logs в stderr (одно событие = одна строка).                                                   |
| NFR-F1-3   | Скрипт работает в Python 3.10+; нет зависимостей от системных пакетов кроме `ffmpeg`, `curl`.                              |
| NFR-F1-4   | API-ключ берётся только из переменной окружения `HEDRA_API_KEY`. Захардкоженных ключей в коде/манифестах нет.              |
| NFR-F1-5   | Сетевые ретраи имеют общий бюджет не больше 30 секунд на один запрос (включая backoff), чтобы не блокировать поток слайдов. |
| NFR-F1-6   | Скрипт устойчив к Ctrl+C: текущий слайд завершается или помечается «interrupted», но manifest остаётся валидным.            |

## F2 — Конвейер слайдов

### Функциональные NR

| ID         | Требование                                                                                  |
|------------|---------------------------------------------------------------------------------------------|
| NR-F2-1    | `slides.json` — единственный источник правды по тексту озвучки.                             |
| NR-F2-2    | При старте сервис валидирует, что все 50 записей содержат `id`, `title`, `narration`.       |
| NR-F2-3    | Для каждого слайда сервис считает `text_sha256` от `narration` и сохраняет в manifest.      |
| NR-F2-4    | Запись manifest атомарна (`tmp` + `rename`).                                                |
| NR-F2-5    | Manifest содержит для каждого слайда: status, hedra_generation_id, file_sha256, duration_sec, generated_at, text_sha256, error. |

### NFR

| ID         | Требование                                                                          |
|------------|-------------------------------------------------------------------------------------|
| NFR-F2-1   | `slides.json` валиден по JSON Schema (см. `data/slides.schema.json`).               |
| NFR-F2-2   | Manifest сериализуется в UTF-8 без BOM, с отступами 2 и стабильной сортировкой ключей. |

## F3 — Плеер

### Функциональные NR

| ID         | Требование                                                                                       |
|------------|--------------------------------------------------------------------------------------------------|
| NR-F3-1    | Страница содержит ровно 50 слайдов (`id="slide-0" .. id="slide-49"`).                            |
| NR-F3-2    | Видео-bubble получает `src = "videos/" + (currentSlide+1) + ".mp4"` при каждой смене слайда.    |
| NR-F3-3    | Клавиатура: → / Space / Enter / PageDown — вперёд; ← / Backspace / PageUp — назад.               |
| NR-F3-4    | Touch swipe: горизонтальный жест ≥ 50px — переключает слайд.                                     |
| NR-F3-5    | Bubble перетаскивается мышью и пальцем, позиция сохраняется в localStorage.                      |
| NR-F3-6    | Клик по bubble — toggle pause/play.                                                              |
| NR-F3-7    | На `?pdf=1` или `#pdf` показываются все слайды одновременно, bubble скрыт.                       |
| NR-F3-8    | Прогресс-бар отражает `(currentSlide+1)/totalSlides`.                                            |

### NFR

| ID         | Требование                                                                                                                        |
|------------|-----------------------------------------------------------------------------------------------------------------------------------|
| NFR-F3-1   | Время до первого слайда (TTI) ≤ 1.5 секунды на хорошем 4G и десктопе (Tailwind через CDN, Phosphor через CDN).                     |
| NFR-F3-2   | Страница рендерится корректно на ширинах 360–1920px без ломок.                                                                     |
| NFR-F3-3   | Цветовая палитра: brand purple `#7c3aed`, brand orange `#f97316`; единая типографика Inter.                                        |
| NFR-F3-4   | Все интерактивные элементы доступны клавиатурой (tab-focus, aria-label на bubble и контролах).                                     |
| NFR-F3-5   | Видео должно гарантированно стартовать после первого пользовательского жеста (требование браузерных autoplay-policy для звука).    |
| NFR-F3-6   | При отсутствии mp4 страница не ломается — продолжает листаться, в bubble показывается placeholder.                                 |

## F4 — Git публикация

### Функциональные NR

| ID         | Требование                                                                                            |
|------------|-------------------------------------------------------------------------------------------------------|
| NR-F4-1    | После генерации сервис делает один коммит со всеми новыми/обновлёнными mp4.                           |
| NR-F4-2    | Push выполняется в ветку `claude/setup-gcloud-video-service-XKVf0`.                                   |
| NR-F4-3    | При сетевом сбое push ретраится до 4 раз с backoff 2/4/8/16s (см. инструкции git репо).               |

### NFR

| ID         | Требование                                                                                                |
|------------|-----------------------------------------------------------------------------------------------------------|
| NFR-F4-1   | Объём одного коммита ≤ 500 MB (рекомендация GitHub). При превышении — сервис останавливается с фатальной ошибкой и рекомендует Git LFS. |
| NFR-F4-2   | Имена видео — `1.mp4 .. 50.mp4`, ASCII, нижний регистр, без пробелов.                                     |
| NFR-F4-3   | Перед push сервис делает `git fetch` и переотрисовывает ветку поверх свежего origin (rebase=false для простоты, проверка отсутствия конфликтов в `l7/videos/`). |

## F5 — gcloud развёртывание

### Функциональные NR

| ID         | Требование                                                                                       |
|------------|--------------------------------------------------------------------------------------------------|
| NR-F5-1    | `bootstrap.sh` идемпотентен: повторный запуск не ломает уже установленную среду.                 |
| NR-F5-2    | `bootstrap.sh` устанавливает: `python3`, `python3-pip`, `python3-venv`, `git`, `ffmpeg`, `curl`. |
| NR-F5-3    | Скрипт создаёт виртуальное окружение `.venv` и ставит `requirements.txt`.                        |

### NFR

| ID         | Требование                                                                                                              |
|------------|-------------------------------------------------------------------------------------------------------------------------|
| NFR-F5-1   | Все секреты только через ENV / Secret Manager. `.gitignore` запрещает `.env`, `*.key`, `secrets/`.                       |
| NFR-F5-2   | VM-инстанс `human-1` в зоне `europe-west1-b`, проект `i-crossbar-433120-v3` — задокументировано в README.                 |
| NFR-F5-3   | Время bootstrap'а на чистой VM ≤ 5 минут (apt + pip install).                                                            |
| NFR-F5-4   | Сервис не зависит от наличия сервисного аккаунта с правами на gcloud (он работает на самой VM, через SSH-сессию).        |
